# GitHub Actions & Secrets Guide (Newbie Tutorial)

This guide explains how **GitHub Actions** workflows work in ShangoHub, what **GitHub Secrets** are, how to set them up, and step-by-step instructions on how to obtain every value.

---

## 1. Quick Summary: What Do You Actually Need to Do?

> [!NOTE]
> **Good news:** If you just want to build and download the Windows `shango-agent.exe` and Linux binary, **you do NOT need to set any secrets!**
> The binary build workflow works 100% out of the box with zero secrets required.

Here is the quick breakdown of all GitHub Secrets across the repository:

| Secret Name | Workflow | Is it Required? | What Happens If You Don't Set It? |
| :--- | :--- | :---: | :--- |
| `DOCKERHUB_USERNAME` | `docker-publish.yml` | **Only if publishing to Docker Hub** | Docker build & push workflow is skipped/fails to push. |
| `DOCKERHUB_TOKEN` | `docker-publish.yml` | **Only if publishing to Docker Hub** | Docker build & push workflow fails to authenticate. |
| `SONAR_TOKEN` | `ci.yml` | **Optional** | Pytest unit tests and Ruff linter run normally; the SonarCloud scan step automatically skips. |
| `WINDOWS_SIGNING_CERT_BASE64` | `build-agent.yml` | **Optional** | The workflow automatically generates a dedicated ShangoHub self-signed Authenticode certificate and signs the `.exe`. |
| `WINDOWS_SIGNING_CERT_PASSWORD` | `build-agent.yml` | **Optional** | Used only if you provided a custom `.pfx` certificate above. |

## 2. Where and How to Add Secrets in GitHub (Click-by-Click)

GitHub Secrets are encrypted credentials stored safely in your repository so that automated workflows can access them without exposing passwords in your code.

### Step-by-Step Instructions:
1. Open your web browser and go to your repository on GitHub:
   ```text
   https://github.com/<your-username>/ShangoHub
   ```
2. Click the **Settings** tab in the top navigation bar (the gear icon on the far right).
3. In the left-hand sidebar menu:
   - Scroll down to the **Security** section.
   - Click to expand **Secrets and variables**.
   - Click on **Actions**.
4. You will see a section called **Repository secrets**. Click the green button: **New repository secret**.
5. Fill in the fields:
   - **Name:** Type the exact secret name in capital letters (e.g. `DOCKERHUB_USERNAME`).
   - **Secret:** Paste your value or token.
6. Click the green button **Add secret**.
7. Repeat this process for any other secrets you wish to add.

```
GitHub Repository -> Settings -> Secrets and variables -> Actions -> "New repository secret"
```

## 3. How to Obtain Each Secret (Step-by-Step)

### A. Docker Hub Secrets (`DOCKERHUB_USERNAME` & `DOCKERHUB_TOKEN`)

These are only required if you want GitHub Actions to automatically build and push the `shango-bot` container image to your Docker Hub account whenever you push code changes.

#### 1. `DOCKERHUB_USERNAME`
- **What it is:** Your Docker Hub account login username (for example, `johndoe`).
- **How to obtain:** 
  1. Go to [https://hub.docker.com](https://hub.docker.com).
  2. If you don't have an account, click **Sign Up** (it's free).
  3. Your username is displayed in the upper-right corner once logged in.

#### 2. `DOCKERHUB_TOKEN`
- **What it is:** A Personal Access Token (PAT) generated by Docker Hub. **Never use your personal password.**
- **How to obtain:**
  1. Log into [https://hub.docker.com](https://hub.docker.com).
  2. Click on your profile username in the top-right corner $\rightarrow$ click **Account Settings**.
  3. In the left sidebar, click **Security**.
  4. Under the *Access Tokens* section, click the blue button **New Access Token**.
  5. Enter a description: `GitHub Actions ShangoHub`.
  6. Under *Access permissions*, select **Read & Write**.
  7. Click **Generate**.
  8. Copy the generated token immediately (it starts with `dckr_pat_...`).
  9. Add this token in GitHub Secrets as `DOCKERHUB_TOKEN`.

---

### B. SonarCloud Secret (`SONAR_TOKEN`)

This is optional. If you use [SonarCloud.io](https://sonarcloud.io) for continuous code quality inspection:

1. Go to [https://sonarcloud.io](https://sonarcloud.io) and click **Log in with GitHub**.
2. Click your user avatar in the top-right corner $\rightarrow$ select **My Account**.
3. Click the **Security** tab.
4. Under *Generate Token*:
   - Enter a name (e.g. `ShangoHub-CI`).
   - Click **Generate**.
5. Copy the generated hex token string.
6. In your GitHub repository $\rightarrow$ Settings $\rightarrow$ Secrets and variables $\rightarrow$ Actions $\rightarrow$ Add Secret:
   - Name: `SONAR_TOKEN`
   - Secret: *(paste token)*

> [!TIP]
> If you don't have a SonarCloud account, **do nothing**. The CI workflow (`.github/workflows/ci.yml`) will detect that `SONAR_TOKEN` is not present and will safely skip the scan while still running 100% of your unit tests and linters.

---

### C. Windows Code-Signing Secrets (Optional)

In `.github/workflows/build-agent.yml`, the build job creates the standalone `shango-agent-windows-x64.exe` binary.

#### If you DO NOT have a commercial certificate (Default):
- **Do nothing!** You don't need any secrets.
- The workflow automatically generates a dedicated self-signed Authenticode certificate (`CN=ShangoHub (GitHub Actions)`), digitally signs the `.exe` with SHA256, and timestamps it with DigiCert's official RFC 3161 timestamp server (`http://timestamp.digicert.com`).

#### If you DO own a commercial Authenticode `.pfx` certificate:
If you have purchased a commercial code-signing certificate (from Sectigo, DigiCert, GlobalSign, etc.):
1. Encode your `.pfx` certificate file into a Base64 string on your computer using PowerShell:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\to\mycert.pfx")) | Set-Clipboard
   ```
2. Add the following secrets in GitHub:
   - Name: `WINDOWS_SIGNING_CERT_BASE64`  
     Value: *(paste the Base64 string from your clipboard)*
   - Name: `WINDOWS_SIGNING_CERT_PASSWORD`  
     Value: *(your `.pfx` certificate password)*

## 4. GitHub Repository Permissions

Standard read permissions are all that's required for the workflow to build and save your binary artifacts.

If you ever see a permission warning:
1. In your GitHub repository, click **Settings** (gear icon).
2. In the left sidebar, click **Actions** $\rightarrow$ **General**.
3. Under **Workflow permissions**, ensure **Read and write permissions** is selected.
4. Click **Save**.

## 5. How to Run the Workflows & Download Binaries

### Option 1: Automatic Trigger
Whenever you push code changes to the `main` branch (`git push origin main`), GitHub Actions automatically:
1. Runs the test suite and quality gates (`ci.yml`).
2. Builds the Windows `.exe` and Linux standalone binaries (`build-agent.yml`).
3. Signs the `.exe` with Authenticode and generates GitHub Sigstore Attestations.

### Option 2: Manual Trigger (Click to Build)
If you want to build the binaries right now without changing code:
1. Go to your GitHub repository and click the **Actions** tab at the top.
2. In the left sidebar, click **Build Agent Binaries (Windows & Linux x64)**.
3. On the right side, click the **Run workflow** dropdown button.
4. Select branch `main` and click the green **Run workflow** button.

### How to Download the Binaries:
1. Once the workflow run finishes (takes ~2 minutes, marked with a green checkmark `✓`):
2. Click on the completed workflow run title.
3. Scroll down to the bottom of the page to the **Artifacts** section:
   - **`shango-agent-windows-x64`**: Contains `shango-agent.exe` (digitally signed) and `shango-agent.cer`.
   - **`shango-agent-linux-x64`**: Contains the standalone Linux 64-bit executable.
4. Click either artifact to download the `.zip` file directly to your computer!

## 6. What About Bot Secrets (`SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`)?

> [!WARNING]
> **Do NOT put your Slack tokens (`xoxb-...` and `xapp-...`) into GitHub Repository Secrets!**
> GitHub Secrets are only for build-time CI/CD workflows.

Your Slack tokens are **runtime secrets** for the bot server when it is running on your LAN or Docker host.
- Keep them on your server inside the `.env` file (see [INSTALL.md](file:///h:/WORKING/ShangoHub/INSTALL.md)).
- The `.gitignore` file guarantees `.env` is never pushed to GitHub.
